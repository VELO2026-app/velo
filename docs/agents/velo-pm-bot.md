# velo_pm_bot — стадия 1 конвейера (вход потока задач)

> Первая карточка фабрики (Фаза 0, п. 8.4 ТЗ) — оформляет де-факто в де-юре: бот уже в бою (п. 8.2). Факты зафиксированы по ТЗ v0.11 (2026-09-16); детальный источник — репозиторий `sstark21/pm-linear-bot`.

- **Статус:** боевой (частично — см. «Состояние»)
- **Репозиторий / место работы:** `sstark21/pm-linear-bot`; прод — приватная группа двух продактов (Вова, Саша) в Telegram, VPS (systemd)
- **Владелец:** sstark; аппрув-гейт — продакт в группе, утверждающий карточку — владелец фабрики

## Тип работы (workflow)

Стадия 1 конвейера (Analysis), частично 2–3: материал продактов (речь, скриншоты, видео, пересланные решения) → сборка и чистка материала → черновик задачи → стандартизованный бриф → Linear после явного ✅. Не чат-бот с командами, а менеджер потока задач.

## Модели

| Назначение | Модель | Fallback |
| --- | --- | --- |
| Черновик задачи, чистка транскрипта | GLM-5.2 | Claude Haiku |

Смена модели — через eval-гейт; `models.yaml` появится в Фазе 2.

## Входы

Голос (дословная транскрипция; различает задачу / уточнение / контекст) · скриншот + подпись (чтение экрана → баг-карточка) · скриншот и текст соседними сообщениями (склейка в один материал) · видео экрана (кадры + звук → сценарий) · .md/.txt (ТЗ, транскрипты созвонов) · пересланные пачкой (один материал) · созвон >15 мин (архив + очередь карточек «1 из N»).

## Инструменты и права (least privilege)

- **Linear** — единственная запись во внешние системы: создание issue + посев-комментарий + Telegraph-бриф, **только после явного ✅ человека**. Аппрувы/мержи в Linear — нет.
- **Telegram Bot API** (локальный) — приём материалов, до 2 ГБ.
- **whisper / gemini** — транскрипция и чтение материалов.
- **Формат `velo seed`** — генерация seed-профилей; на стенде применяется человеком (`velo seed --profile FE-XX --reset`), в профиле прописан сценарий проверки `_verify`.
- **SQLite** — аудит аппрувов.
- Production-инфраструктура velo — доступа нет (правило п. 8.5.1).

## Источники контекста

Приватная группа продактов (вся история как материал) · живой Linear (валидация черновика против реальных issue) · упомянутые issue (в разработке, BE-14) · формат `velo seed` (посевы).

## Evals (п. 5.6)

- **Сейчас:** 340 pytest-тестов конвейера в репо бота (детерминированный контур) + принципы честности как инварианты («в описании только ссылка — пришли документ», а не фантазия).
- **Долг карточки:** формализованный eval-набор на исторических материалах (методика п. 5.3/5.6) — завести при Фазе 2; до тех пор статус «боевой» оправдан живой эксплуатацией, а не eval-гейтом.
- **Когда гоняются:** при любой смене модели/промптов — блокирующий гейт.

## Правила эскалации к человеку

- Уточнения — кнопками, ≤3 варианта; исходное сообщение помнится.
- Ошибки честные по источнику: «не удалось скачать вложение» ≠ «Linear недоступен».
- Деградация к базовому пути без блокировки материала.
- Аппрув — единственный путь записи в Linear; комментарий агента аппрувом не считается никогда (п. 8.5.5).

## Метрика: cost per useful outcome

- **Useful outcome:** подтверждённая ✅ карточка → issue в Linear + посев-комментарий + бриф, принятые продактом.
- **Текущее значение:** не считается до Фазы 5; с даты карточки владелец считает вручную число полезных карточек за период.

## Состояние (сентябрь 2026, из ТЗ п. 8.2)

- **В бою:** голос→задача, текст→задача, скриншот+подпись→баг с посевом, уточнения кнопками, .md-ТЗ.
- **Задеплоено, ждёт боевых прогонов:** очередь «1 из N», Telegraph-статьи, /summary, создание проектов, видео-кадры.
