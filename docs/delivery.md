# Поставка velo: ветки, стенды, сборки

> Правила поставки. Документ меняют вместе с ними: в той же поставке, что меняет ветки, задания CI или контракт с машиной.
> Блок «Состояние» в конце датирован и устаревает первым: обновлять его при каждом сдвиге стендов.
> Версии соседей здесь не повторяются. Источник — `primer.lock`.

## Ветки

- **deploy-machine** — единственная рабочая ветка, весь продукт: бэк и фронт. С 12.11.2026 в неё слит `test` (BE-208). Это ветка по умолчанию в репозитории: на неё смотрят ночной обход e2e и Dependabot.
- **test** — заморожен на `44083fba`. В него больше ничего не вливается. Его продолжает выкатывать шелл-стенд, пока не встанет velo-test.
- **main** — прод на шелле до переноса прода на машину. Его не трогаем.

## Как вносить изменения

- PR в `deploy-machine`. Слияние — на сайте GitHub кнопкой «Create a merge commit».
- В сообщении каждого коммита после пустой строки — трейлер `Task: <номер карточки>`, например `Task: FE-188`. Машина берёт из него задачу коммита: красный выкат блокирует стенд задачей своего коммита.

## Стенды и серверы

- **Шелл-стенд** (velotony.com, api.velotony.com) — замороженный `test` через `velo update`. Живой, но устаревший: служит эталоном, пока не встанет velo-test.
- **Прод** — `main`, на шелле.
- **velo-test** — первая установка velo машиной Праймера, на dev-сервер (zxcvbnm.beer). Ставится по ветке `deploy-machine` (роль test).
- **Перенос прода** — после зелёного velo-test: репетиция на копии дампа, паспорт прода, тег релиза `vX.Y.Z` (прод машина ставит только по тегу), перенос (BE-200).

## Сборки и CI (deploy-machine)

- **«CI»** (`ci.yml`) — линт, тесты фронта и `@velo/ui`, сборка, Playwright smoke, e2e на живом бэке (`e2e-stack.yml`), сборка и smoke образа фронта, матрица скинов, drift `generated.ts`.
  - Задание `scope` классифицирует и PR, и пуш (`before..sha`): поставка без фронта задания фронта не гоняет. Если разницу пуша не вычислить — гоняется всё.
  - Визуальная сверка (visual — base vs head) — только на PR, информационная.
- **«Backend tests»** (`backend-tests.yml`) — полная сьюта бэка на живых Postgres, Redis и RustFS, включая проверку хранилища так, как её запускает глагол машины.
- **«Primer check»** (`primer-check.yml`) — `pridem check` машины (ставится из её релиза по sha256) по `primer.yaml`, `primer.lock` и compose обоих стеков.
- **Ночной обход e2e** (e2e sweep) — по расписанию на ветке по умолчанию, Chromium и WebKit; вручную — «Run workflow». Инструкция — `docs/agents/e2e.md`.
  - Детектор сбоев знает безвредное предупреждение WebKit о `interactive-widget` — только его, точным текстом и только в WebKit.
  - Одноразовое приглашение мастера выпускается на каждый проект Playwright отдельно (FE-188).

## Фронт под машиной

- Образ фронта собирает машина при установке, из репозитория. Значения инстанса приходят при старте контейнера в `/config.json`: адреса, языки, шесть флагов опций (`OPTION_*`).
- `generated.ts` теперь генерирует и машина: раздел `types` в `primer.yaml`. На роли test она коммитит его в ветку ключом записи. Пока жив drift-check в CI, изменение API по-прежнему приносит перегенерированный `generated.ts` в той же поставке.
- Редакция одна — `ai` (`editions.json`). Что видно на экране, решают флаги опций, а не редакции.
- Скин — слот `packages.skin`, контракт поколения 2 (`SKIN_CONTRACT_MAJOR = 2`), необязательный: нет пакета в паспорте — золотая сборка VELO.
- Тексты инстанса — слот `packages.texts`, `apply: runtime`: пакет монтируется целиком в `/srv/texts`, nginx отдаёт `/texts/ui/`, проверка пакета — `validate-texts`. Оверлей писем comms пока не принимает.
- Вход через Telegram: Mini App — токеном бота; токен velo берёт швом от comms. Браузер — OIDC, ключи клиента — значения velo. Переход Mini App на открытый ключ Telegram — после переноса прода (BE-183).
