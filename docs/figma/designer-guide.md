# Таня, это инструкция к твоему помощнику в Figma

Помощник — это Codex от OpenAI (тот же ChatGPT, только с доступом к программам на твоём
компьютере), которому дали доступ к нашему файлу Figma «VELΘ App Актуальное». Он умеет
начать эксперимент с копии экрана, проверить макет перед передачей разработчикам,
перенести готовый макет куда нужно, завести задачу и показать, чем макет отличается от
того, что сейчас в приложении.

Установить один раз — минут двадцать-тридцать. Если где-то застрянешь, напиши Владимиру:
он поможет, это нормально.

Почему так, а не через официальный Figma MCP: у официального на бесплатном тарифе всего
20 обращений в месяц. Мы используем открытый плагин **Figma Desktop Bridge** из проекта
figma-console-mcp (https://github.com/southleft/figma-console-mcp). Он работает через
обычный API плагинов Figma, у которого лимитов нет. Помощник через него видит и правит
файл почти как через официальный (кадры, тексты, компоненты, переменные; нет только
Code Connect, он нам не нужен). Работает на macOS и Windows.

Почему Codex, а не обычный чат ChatGPT: помощнику нужно запускать на твоём компьютере
связку с Figma (сервер figma-console). Это умеет Codex: в Терминале (Codex CLI) и в
приложении ChatGPT для компьютера, у них общие настройки. Чат на сайте так не умеет.

## Что понадобится

- Mac или компьютер с Windows.
- Приложение **Figma** (именно приложение, не сайт в браузере) и доступ на редактирование
  к файлу «VELΘ App Актуальное».
- Аккаунт ChatGPT с доступом к Codex (тарифы Plus, Pro, Business и выше; Владимир скажет,
  какой аккаунт использовать). Саму программу Codex поставишь в шаге 2.
- Аккаунт в Linear (у тебя он уже есть).
- Архив `velo-figma-designer-<версия>.zip` — во вложениях задачи DSGN-31.

## Шаг 1. Node.js

Это служебная программа, через которую помощник разговаривает с Figma.
Скачай и установи версию **LTS** с сайта https://nodejs.org (обычная установка, «Далее»
до конца).

## Шаг 2. Codex

1. Открой программу **Терминал** (Cmd + пробел → «Терминал»). На Windows — **PowerShell**
   (Пуск → «PowerShell»).
2. Вставь команду и нажми Enter:
   - Mac: `curl -fsSL https://chatgpt.com/codex/install.sh | sh`
   - Windows: `powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 | iex"`

   Если команда не сработала: на Mac с Homebrew — `brew install --cask codex`, иначе
   `npm install -g @openai/codex`. Если npm пишет `EACCES` (нет прав), не используй `sudo`:
   поставь через Homebrew или напиши Владимиру.
3. **Закрой Терминал и открой заново** (так он узнает о новой программе).
4. Сделай папку для работы с помощником и запусти его там. Вставь по очереди:
   - Mac: `mkdir -p ~/Documents/figma-assistant && cd ~/Documents/figma-assistant && codex`
   - Windows: `mkdir $HOME\Documents\figma-assistant; cd $HOME\Documents\figma-assistant; codex`
5. При первом запуске выбери **Sign in with ChatGPT** — откроется браузер, войди своим
   аккаунтом. Если спросит, доверяешь ли папке, — ответь «да». Папка может быть любой,
   просто запускай помощника всегда из неё.
6. Чтобы выйти, набери `/quit` (или нажми Ctrl + C два раза). Чтобы запустить снова —
   открой Терминал и вставь команду из пункта 4.

Можно работать и в приложении ChatGPT для компьютера (раздел Codex; открыть его можно
командой `codex app`): настройки у него общие с Терминалом, помощник там тот же. Если в
приложении помощник не видит Figma, работай в Терминале и напиши Владимиру.

## Шаг 3. Поставить помощника для Figma

1. Распакуй `velo-figma-designer-<версия>.zip` (двойной щелчок). Появится папка `velo-figma-designer`.
2. В Терминале напечатай `bash ` (с пробелом в конце), перетащи в окно Терминала файл
   `install.sh` из папки и нажми Enter.
3. В конце должно быть «Готово». Галочки ✔ — всё хорошо. Крестик ✘ — рядом написано, что
   сделать; сделай и запусти ещё раз.

**Если у тебя Windows.** Файл `install.sh` рассчитан на Mac. На Windows запусти помощника
(шаг 2, пункт 4) и напиши ему:

> скопируй папку <путь к распакованной папке velo-figma-designer> (SKILL.md, scripts и
> references) в .agents\skills\velo-figma-designer в моей домашней папке и добавь в
> .codex\config.toml в моей домашней папке два MCP-сервера: figma-console (command = "npx",
> args = ["-y", "figma-console-mcp@1.46.0"], startup_timeout_sec = 90, tool_timeout_sec = 120)
> и linear (url = "https://mcp.linear.app/mcp")

## Шаг 4. Плагин в Figma (один раз)

1. Запусти помощника (шаг 2, пункт 4) и напиши «привет». Это создаст файлы плагина на
   компьютере (первый запуск может занять минуту). Если помощник уже был открыт до
   шага 3 — выйди и запусти заново.
2. В Figma открой файл «VELΘ App Актуальное».
3. Меню Figma → **Plugins → Development → Import plugin from manifest…**
4. В окне выбора нажми Cmd + Shift + G, вставь `~/.figma-console-mcp/plugin/manifest.json`,
   Enter, «Открыть». На Windows путь: `%USERPROFILE%\.figma-console-mcp\plugin\manifest.json`.
5. Теперь запусти: **Plugins → Development → Figma Desktop Bridge**. Появится маленькое
   окно плагина. **Не закрывай его**, пока работаешь с помощником (можно свернуть в сторону).

Каждый раз, когда открываешь Figma для работы с помощником, запускай плагин (пункт 5).

Помощник иногда спрашивает разрешение: выполнить действие с Figma (инструменты figma-console),
запустить команду или поправить свои настройки. Для работы с Figma и Linear отвечай «да»
(можно выбрать «да, и не спрашивать в этой сессии»). Если просит удалить что-то или работать
вне папки помощника — сначала спроси Владимира.

## Шаг 5. Проверить, что всё работает

Напиши помощнику:

> проверь подключение к фигме

Он должен ответить, что подключён к файлу «VELΘ App Актуальное». Если пишет, что плагин не
подключён, — запусти плагин (шаг 4, пункт 5) и напиши «готово».

Потом Linear: выйди из помощника, в Терминале вставь `codex mcp login linear` и войди своим
аккаунтом Linear в открывшемся браузере. Запусти помощника снова и проверь:

> покажи мои задачи в Linear

Помощника для Figma можно позвать и по имени: напиши `$velo-figma-designer` и свою просьбу.

## Как устроен файл

Файл поделён на две части.

**Фронт** — это то, что сейчас есть в приложении: экраны, кнопки, карточки, цвета. Эти
страницы обновляют разработчики, когда что-то меняется в коде. **Здесь ничего не правим** —
только смотрим и берём готовые кнопки и карточки в свои макеты.

- `Фронт · Экраны` — экраны приложения как они есть.
- `Фронт · Kit и токены` — кнопки, карточки, иконки, цвета, размеры текста.
- `Фронт · Скины` — как приложение выглядит у каждого бренда: ядро (нейтральный вид без
  бренда), золотой VELO и Goodo. Скин меняет
  только цвета, логотипы и фон, расположение экранов одинаковое, поэтому рисовать экран под
  каждый бренд не нужно.

Цвета и размеры в Figma — переменные коллекции `velo` с тремя режимами: `core` (ядро, серый
нейтральный вид), `gold` (VELO) и `goodo`. Кадр показывает режим, который выставлен на нём или
на его странице (панель справа, раздел Appearance → `velo`). Где режим не выставлен, Figma
показывает режим по умолчанию — `core`. Чтобы кнопка из кита у тебя выглядела как в VELO,
выставь странице или кадру режим `gold`; чтобы посмотреть Goodo — `goodo`. Сами значения
режимов не правь: их заливает из кода разработчик.

**Дизайн** — твоя зона.

- `Icons`, `User App`, `Master App`, `Admin Panel` — твои прежние страницы, как были.
- `Эксперименты · <тема>` — рисуй как хочешь, правил почти нет.
- `К разработке` — сюда попадают одобренные макеты. Разработчики берут их отсюда.
- `Архив` — то, что уже сделано в приложении или отменено.

С 20.11 файл перестроен. Твои страницы `Icons`, `User App`, `Master App`, `Admin Panel` не
менялись: те же имена, то же содержимое. Добавились `Фронт · …`, `К разработке`,
`Эксперименты · Goodo` и `Архив`. Страница `front` осталась, но пустая: на неё ничего не клади. Наверху файла — `Обложка` с этой же схемой.

Путь макета: эксперимент → на согласование → Alexandra одобрила в задаче DSGN → «К разработке» и задача для разработчиков →
разработчики делают → макет уезжает в архив, а новый экран появляется на «Фронт».

## Что можно просить (примеры фраз)

1. **«Начни эксперимент про Сонник с экрана дневника»** — создаст страницу эксперимента
   и положит туда копию экрана из «Фронт». В копии кнопки и карточки остаются «живыми».
2. **«Проверь кадр <ссылка>»** — скажет, что мешает передать макет разработчикам и что
   желательно поправить. Ссылка: правый клик по кадру → Copy/Paste as → Copy link to selection.
3. **«Подготовь к разработке <ссылка>»** — то же, плюс предложит исправить простое
   (названия слоёв, стили текста, цвета и отступы из палитры). Исправит, только когда ты
   скажешь «да».
4. **«Отправь на согласование <ссылки>, задача DSGN-30»** — когда проверка чистая.
   Помощник составит комментарий в задачу DSGN: упомянет Alexandra и даст ссылки на кадры
   (и Владимира, если в макете новый компонент или заявка на токен ещё не одобрена). Покажет тебе текст и после твоего
   «да» отправит его от твоего имени. Одобрение Alexandra пишет ответом там же, в DSGN
   (как — в её [памятке](https://linear.app/velo-space/document/pamyatka-dlya-pm-kak-odobryat-makety-k-razrabotke-f7f3379b46da)); «да» в чате помощник не примет.
5. **«Передай в разработку <ссылка>, задача DSGN-30»** — если макет лежит на твоих страницах
   (`User App` и т. п.), сначала скопирует его в эксперимент, оригинал останется на месте. Потом перенесёт копию в «К разработке»,
   проверит его ещё раз уже там и найдёт задачу для разработчиков. Задачу, указанную в
   DSGN, возьмёт сам; найденную поиском в Linear или уже начатую — только после твоего
   «да»; если задачи нет — заведёт. Только если макет
   одобрен и проверка чистая; если после переноса найдётся ошибка, вернёт макет обратно.
6. **«Предложи токен <цвет, отступ или радиус>»** — когда нужного цвета или размера нет в
   палитре. Помощник сначала поищет похожий токен и, если найдёт, предложит взять его. Если
   нет, составит заявку в Linear («Токен: имя = значение», метка `token`), покажет тебе текст
   и после твоего «да» заведёт её. Владимир одобряет заявку в Linear. Пока она не одобрена,
   кадр со своим значением передать нельзя.
7. **«Покажи, чем макет отличается от фронта <ссылка>»** — сравнит с экраном из
   приложения: какие блоки, тексты, кнопки и цвета другие.
8. **«Обнови статусы»** — посмотрит в Linear, что уже в работе и что готово, отметит это на
   макетах и уберёт сделанное в архив.
9. **«Что сейчас на фронте на экране профиля?»** — покажет экран, как он есть в приложении.

## Что помогает макету пройти проверку

- Ширина экрана **402**. Название кадра: `Экран / Состояние / 402`, например
  `Профиль / Default / 402`.
- Кнопки, карточки, шапка, нижнее меню — **из «Фронт · Kit и токены»** (перетащить
  компонент), а не нарисованные заново.
- Цвета, отступы и радиусы — только из палитры файла (переменные страницы «Фронт · Kit и
  токены»), своё значение — через заявку на токен, текст — шрифт **Marmelad** и стиль `velo/fs-…`.
- Auto Layout в блоках, понятные названия слоёв (`Header`, `title`, а не `Frame 12`).
- Новый цвет, отступ или радиус — «Предложи токен». Помощник заведёт заявку в Linear, а в
  заметке «Новое» будет строка со ссылкой на неё (`Новые токены: имя = значение — FE-NNN`).
  Владимир одобряет заявку в Linear (переводит в Todo или пишет «одобрено»). Слова «одобрено» в
  заметке проверку не пройдут: нужна заявка, которую одобрили. Тогда сырое значение будет
  предупреждением, а не ошибкой. Какой статус заявки что значит для проверки — таблица в
  протоколе, §10 п. 6 (лежит в папке `references` рядом с помощником).
- Новая кнопка или другой компонент — помощник поможет описать в заметке «Новое». Владимир
  одобряет: строка в заметке с пометкой «одобрено, кто, дата».
- Новая иконка — в заметке «Новое».
- Новая иконка — отдельный компонент `icon/<название>`, квадратный, одного цвета.

В экспериментах всё это не обязательно. Требования нужны только при передаче.

## Чего помощник делать не будет

- Менять страницы «Фронт», обложку, палитру (переменные), стили текста и готовые кнопки
  и карточки кита. Новый цвет или компонент он оформит как предложение.
- Передавать макет в разработку без одобрения или с ошибками проверки.
- Удалять чужие макеты и страницы. Удалить может только то, что сам создал.
- Писать код приложения — это делают разработчики и их помощник.

## Если что-то не работает

- «Плагин не подключён» — запусти **Plugins → Development → Figma Desktop Bridge** в
  открытом файле и не закрывай окно плагина.
- «Страница занята» — на этой странице сейчас работает другой помощник (например,
  разработчиков). Он сам освободит её, самое долгое через 30 минут. Подожди или напиши
  Владимиру.
- «Не удалось сохранить версию» — помощник ничего не поменял и спрашивает, можно ли
  работать без точки отката. Если не уверена — ответь «нет» и напиши Владимиру.
- `command not found: codex` — закрой и снова открой Терминал; не помогло — повтори шаг 2.
- Помощник сделал не то — напиши ему «верни как было»: перед каждой правкой он сохраняет
  версию файла (Figma → File → Show version history).
- Всё остальное — Владимиру, со скриншотом.
