# Таня, это инструкция к твоему помощнику в Figma

Помощник — это Claude, которому дали доступ к нашему файлу Figma «VELΘ App Актуальное».
Он умеет начать эксперимент с копии экрана, проверить макет перед передачей
разработчикам, перенести готовый макет куда нужно, завести задачу и показать, чем
макет отличается от того, что сейчас в приложении.

Установить один раз — минут двадцать-тридцать. Если где-то застрянешь, напиши Владимиру:
он поможет, это нормально.

Почему так, а не через официальный Figma MCP: у официального на бесплатном тарифе всего
20 обращений в месяц. Мы используем открытый плагин **Figma Desktop Bridge** из проекта
figma-console-mcp (https://github.com/southleft/figma-console-mcp). Он работает через
обычный API плагинов Figma, у которого лимитов нет. Помощник через него видит и правит
файл почти как через официальный (кадры, тексты, компоненты, переменные; нет только
Code Connect, он нам не нужен). Работает на macOS и Windows.

## Что понадобится

- Mac или компьютер с Windows.
- Приложение **Figma** (именно приложение, не сайт в браузере) и доступ на редактирование
  к файлу «VELΘ App Актуальное».
- Аккаунт Claude с доступом к Claude Code (Владимир даст доступ). Саму программу Claude
  Code поставишь в шаге 2.
- Аккаунт в Linear (у тебя он уже есть).
- Архив `velo-figma-designer.zip` — во вложениях задачи DSGN-31.

## Шаг 1. Node.js

Это служебная программа, через которую помощник разговаривает с Figma.
Скачай и установи версию **LTS** с сайта https://nodejs.org (обычная установка, «Далее»
до конца).

## Шаг 2. Claude Code

Это и есть помощник: программа, с которой ты переписываешься в Терминале.

1. Открой программу **Терминал** (Cmd + пробел → «Терминал»). На Windows — **PowerShell**
   (Пуск → «PowerShell»).
2. Вставь команду и нажми Enter:
   - Mac: `curl -fsSL https://claude.ai/install.sh | bash`
   - Windows: `irm https://claude.ai/install.ps1 | iex`

   Если команда не сработала, вставь вместо неё `npm install -g @anthropic-ai/claude-code`.
3. **Закрой Терминал и открой заново** (так он узнает о новой программе).
4. Сделай папку для работы с помощником и запусти его там. Вставь по очереди:
   - Mac: `mkdir -p ~/Documents/figma-assistant && cd ~/Documents/figma-assistant && claude`
   - Windows: `mkdir $HOME\Documents\figma-assistant; cd $HOME\Documents\figma-assistant; claude`
5. При первом запуске помощник попросит войти — откроется браузер, войди своим аккаунтом
   Claude. Потом спросит, доверяешь ли этой папке — ответь «да». Папка может быть любой,
   просто запускай помощника всегда из неё.
6. Чтобы выйти из помощника, набери `/exit`. Чтобы запустить снова — открой Терминал и
   вставь команду из пункта 4.

## Шаг 3. Поставить помощника для Figma

1. Распакуй `velo-figma-designer.zip` (двойной щелчок). Появится папка `velo-figma-designer`.
2. В Терминале напечатай `bash ` (с пробелом в конце), перетащи в окно Терминала файл
   `install.sh` из папки и нажми Enter.
3. В конце должно быть «Готово». Галочки ✔ — всё хорошо. Крестик ✘ — рядом написано, что
   сделать; сделай и запусти ещё раз.

**Если у тебя Windows.** Файл `install.sh` рассчитан на Mac. На Windows запусти помощника
(шаг 2, пункт 4) и напиши ему:

> поставь скилл из папки <путь к распакованной папке velo-figma-designer> в мои скиллы
> Claude Code (копия SKILL.md, scripts и references в папку .claude\skills\velo-figma-designer
> в моей домашней папке), подключи сервер figma-console версии 1.46.0 по
> https://github.com/southleft/figma-console-mcp и сервер Linear https://mcp.linear.app/mcp

## Шаг 4. Плагин в Figma (один раз)

1. Запусти помощника (шаг 2, пункт 4) и напиши «привет». Это создаст файлы плагина на
   компьютере. Если помощник уже был открыт до шага 3 — выйди (`/exit`) и запусти заново.
2. В Figma открой файл «VELΘ App Актуальное».
3. Меню Figma → **Plugins → Development → Import plugin from manifest…**
4. В окне выбора нажми Cmd + Shift + G, вставь `~/.figma-console-mcp/plugin/manifest.json`,
   Enter, «Открыть». На Windows путь: `%USERPROFILE%\.figma-console-mcp\plugin\manifest.json`.
5. Теперь запусти: **Plugins → Development → Figma Desktop Bridge**. Появится маленькое
   окно плагина. **Не закрывай его**, пока работаешь с помощником (можно свернуть в сторону).

Каждый раз, когда открываешь Figma для работы с помощником, запускай плагин (пункт 5).

## Шаг 5. Проверить, что всё работает

Напиши помощнику:

> проверь подключение к фигме

Он должен ответить, что подключён к файлу «VELΘ App Актуальное». Если пишет, что плагин не
подключён, — запусти плагин (шаг 4, пункт 5) и напиши «готово».

Потом Linear: напиши помощнику `/mcp`, выбери **linear**, нажми **Authenticate** и войди
своим аккаунтом. Проверка:

> покажи мои задачи в Linear

## Как устроен файл

Файл поделён на две части.

**Фронт** — это то, что сейчас есть в приложении: экраны, кнопки, карточки, цвета. Эти
страницы обновляют разработчики, когда что-то меняется в коде. **Здесь ничего не правим** —
только смотрим и берём готовые кнопки и карточки в свои макеты.

- `Фронт · Экраны` — экраны приложения как они есть.
- `Фронт · Kit и токены` — кнопки, карточки, иконки, цвета, размеры текста.
- `Фронт · Скины` — как приложение выглядит у каждого бренда: золотой VELO и Goodo. Скин меняет
  только цвета, логотипы и фон, расположение экранов одинаковое, поэтому рисовать экран под
  каждый бренд не нужно.

**Дизайн** — твоя зона.

- `Эксперименты · <тема>` — рисуй как хочешь, правил почти нет.
- `К разработке` — сюда попадают одобренные макеты. Разработчики берут их отсюда.
- `Архив` — то, что уже сделано в приложении или отменено.

Пока файл не перестроен (план ждёт одобрения Владимира), страниц «Фронт · …» ещё нет:
кнопки, карточки, цвета и иконки из приложения лежат на странице `front`, а старые
страницы `User App`, `Master App`, `Admin Panel`, `Icons` остаются как есть. Помощник это знает.

Путь макета: эксперимент → одобрили → «К разработке» и задача для разработчиков →
разработчики делают → макет уезжает в архив, а новый экран появляется на «Фронт».

## Что можно просить (примеры фраз)

1. **«Начни эксперимент про Сонник с экрана дневника»** — создаст страницу эксперимента
   и положит туда копию экрана из «Фронт». В копии кнопки и карточки остаются «живыми».
2. **«Проверь кадр <ссылка>»** — скажет, что мешает передать макет разработчикам и что
   желательно поправить. Ссылка: правый клик по кадру → Copy/Paste as → Copy link to selection.
3. **«Подготовь к разработке <ссылка>»** — то же, плюс предложит исправить простое
   (названия слоёв, стили текста, цвета и отступы из палитры). Исправит, только когда ты
   скажешь «да».
4. **«Передай в разработку <ссылка>, задача DSGN-30»** — перенесёт макет в «К разработке»,
   проверит его ещё раз уже там и заведёт задачу для разработчиков. Только если макет
   одобрен и проверка чистая; если после переноса найдётся ошибка, вернёт макет обратно.
5. **«Покажи, чем макет отличается от фронта <ссылка>»** — сравнит с экраном из
   приложения: какие блоки, тексты, кнопки и цвета другие.
6. **«Обнови статусы»** — посмотрит в Linear, что уже в работе и что готово, отметит это на
   макетах и уберёт сделанное в архив.
7. **«Что сейчас на фронте на экране профиля?»** — покажет экран, как он есть в приложении.

## Что помогает макету пройти проверку

- Ширина экрана **402**. Название кадра: `Экран / Состояние / 402`, например
  `Профиль / Default / 402`.
- Кнопки, карточки, шапка, нижнее меню — **из «Фронт · Kit и токены»** (перетащить
  компонент), а не нарисованные заново.
- Цвета и отступы — из палитры файла (переменные), текст — шрифт **Marmelad** и стиль `velo/fs-…`.
- Auto Layout в блоках, понятные названия слоёв (`Header`, `title`, а не `Frame 12`).
- Всё новое (новый цвет, новая кнопка, новая иконка) — помощник поможет описать в
  заметке «Новое». Новый цвет или размер нужно одобрить: строка в заметке с пометкой
  «одобрено, кто, дата». Тогда проверка его пропустит.
- Новая иконка — отдельный компонент `icon/<название>`, квадратный, одного цвета.

В экспериментах всё это не обязательно. Требования нужны только при передаче.

## Чего помощник делать не будет

- Менять страницы «Фронт», обложку, палитру (переменные), стили текста и готовые кнопки
  и карточки кита. Новый цвет или компонент он оформит как предложение.
- Передавать макет в разработку без одобрения или с ошибками проверки.
- Удалять чужие макеты и страницы. Удалить может только то, что сам создал.
- Писать код приложения — это делают разработчики и их помощник.

## Если что-то не работает

- «Плагин не подключён» — запусти **Plugins → Development → Figma Desktop Bridge** в
  открытом файле и не закрывай окно плагина.
- «Страница занята» — на этой странице сейчас работает другой помощник (например,
  разработчиков). Он сам освободит её, самое долгое через 30 минут. Подожди или напиши
  Владимиру.
- «Не удалось сохранить версию» — помощник ничего не поменял и спрашивает, можно ли
  работать без точки отката. Если не уверена — ответь «нет» и напиши Владимиру.
- `command not found: claude` — закрой и снова открой Терминал; не помогло — повтори шаг 2.
- Помощник сделал не то — напиши ему «верни как было»: перед каждой правкой он сохраняет
  версию файла (Figma → File → Show version history).
- Всё остальное — Владимиру, со скриншотом.
