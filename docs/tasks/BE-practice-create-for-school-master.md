# BE: создание практики для другого мастера (`master_id` на POST /practices)

**Стопер для:** FE-задачи «Включить создание практики для мастера школы»
(фронтовая заглушка уже живёт на странице создания практики и ждёт этот контракт).

## Контракт

`POST /api/v1/practices` — добавить в `CreatePracticeRequest` опциональное поле:

```python
master_id: UUID | None = None
```

Семантика — делегирование владельца школы (§1.6 ТЗ куратора):

- **нет поля или `master_id == caller.id`** → практика принадлежит вызывающему
  (текущее поведение, байт-в-байт);
- **чужой `master_id`** → разрешён ТОЛЬКО когда вызывающий владеет хотя бы одной
  curator group (школой), в которой целевой мастер состоит участником с
  `kind='master'` и его профиль verified прямо сейчас (тот же критерий
  видимости, что у ростера и `masters_count`). Иначе — **403** `ForbiddenError`
  (никакой тихой перезаписи на себя);
- эффективный мастер продевается через ВСЕ мастеро-ключевые места
  `create_practice`: окно дедупликации и race-lookup
  (`uq_practice_master_title_scheduled_recurrence`),
  `_assert_master_confirmed_taxonomy` (подтверждённые методы ЦЕЛЕВОГО мастера),
  `Practice(master_id=...)`, структурные логи.

Проверка принадлежности школе — один запрос:
`CuratorGroup (curator_user_id = caller) JOIN CuratorGroupMember (user_id = target, kind = 'master')`
+ коррелированный EXISTS по `master_profiles.data['account']['status'] == 'verified'`
(как `_verified_profile_exists` в curator_groups/service.py).

## Черновик уже проверен локально

Реализация (~60 строк: schemas + сервис) и 4 интеграционных теста были
написаны и проходили локально (диапазон 89690–89709):

1. владелец школы создаёт для своего видимого мастера → 201, `practice.master_id == target`;
2. чужой верифицированный мастер → 403;
3. участник школы без верифицированного профиля → 403 (видимость = членство + verified);
4. `master_id == self` → 201, владелец = вызывающий.

Нюанс тестов: `full_cleanup_range` из tests/helpers.py не знает curator_groups —
файлу нужен свой клинап групп (invites → members → groups, коммит ДО вызова
хелпера — ловушка H-R1: защитный rollback хелпера стирает незакоммиченные
удаления).

## Примечание

`can_create_groups` (GT-15) на путь не влияет: проверка требует лишь владения
школой, а не права её основать.
