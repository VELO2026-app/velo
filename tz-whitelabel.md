# ТЗ: Whitelabel — фронтовая часть

> Редакция 3, 2026-10-16 (ред. 3 — строгое ревью: честный механизм вырезания
> чанков §4, механизм каскада и тест-механика §3, фактический набор
> бренд-ассетов §3, единый источник «цвета шапки» §1, границы
> брендирования §7). Редакция 2: скоуп сужен до фронта.
> Скоуп: **только `frontend/src`**. Деплой, паспорта,
> центр, Zoom-пул, общие практики, платежи, боты — не здесь (их состав задаёт
> архитектурный документ «VELO: текущая архитектура и вариант с инстансами
> школ» от 16.10.2026); фронт определяет лишь **контракт входов** — форму,
> в которой паспорт приезжает в сборку. i18n не дублируется — см. `tz-i18n.md`
> (фаза 0.5 и §7).

## 0. Резюме

Цель фронтовой части: **один код собирается в N брендированных сборок
без правок кода** — только конфиг и скин-пакет. Всё остальное — следствия.

| Фаза | Что делается | Оценка |
|---|---|---|
| F1. Швы паспорта | конфиг-модуль, index.html/manifest/theme-color из конфига | 2–3 дня |
| F2. Скин, слой 1 | контракт пакета, валидатор, применение на сборке, эталонные скины | 5–8 дней |
| F3. Редакции на фронте | фича-реестр из паспорта, роут-гейт, табы, ленивые чанки | 5–8 дней |
| F4. i18n-швы | локали/`{brand}`/оверлеи инстанса — уже спланированы в `tz-i18n.md` | (там же) |
| F5. Приёмка whitelabel | сборочная матрица, валидатор пакета, греп-тесты бренда | 2–3 дня |

Итого фронт: **~3–4 недели**. Все фазы заканчиваются зелёным `pnpm verify`
и выкатываются независимо; золотая сборка (VELO без скина) бит-в-бит
сохраняется на каждом шаге.

## 1. Контракт входов (что фронт ждёт от паспорта)

Фронт не решает, откуда паспорт берётся, — только форму входов. Каждый шов
имеет дефолт, равный текущему поведению, поэтому базовая сборка не меняется:

| Шов | Дефолт | Кто потребляет |
|---|---|---|
| `VITE_API_BASE_URL` | текущий | `platform` (есть) |
| `VITE_TELEGRAM_BOT_URL` | текущий | вход/бот-ссылки (есть) |
| `VITE_DEFAULT_LOCALE` | `'ru'` | i18n `fallbackLocale`, дефолты `format.ts`, `<html lang>` |
| `VITE_LOCALES` | `'ru'` | лоадер локалей (какие чанки вообще собирать) |
| `VITE_BRAND` | `'VELO'` | `{brand}`-интерполяция в сообщениях, манифест, `<title>` |
| `VITE_FEATURES` | `'full'` | фича-реестр F3 (включённые модули) |
| скин-пакет | отсутствует = эталон VELO | F2 (токены, ассеты, theme-color) |
| производные сборки | генерируются из `skin/brand.json`: theme-color в index.html, цвета/иконки манифеста, ссылка на шрифт | index.html, `pwa/manifest.ts` |

**Единый источник «цвета шапки»** (строгое ревью): сегодня он живёт в трёх
несвязанных местах — `meta theme-color` `#334D6E` в index.html, CSS-токен
`--velo-tg-header` (его читает `platform/telegram.ts:60` с фолбэком
`#334d6e`) и `theme_color` манифеста. Контракт: brand.json — единственный
источник, сборка порождает из него все три потребителя; иначе скин меняет
одно, а статусбар iOS и шапка Telegram остаются VELO-цвета.

## 2. F1 — швы паспорта

1. **`platform/instance.ts`** — единственная точка чтения env: типизированный
   доступ + дефолты. Сегодня `import.meta.env.*` разбросан точечно (5+2
   вхождения) — свести в один модуль, чтобы новый шов добавлялся в одном
   месте.
2. **`index.html` из конфига**: Vite нативно подставляет `%VITE_*%` в
   index.html — плагины не нужны. Значения, приходящие из скина
   (theme-color, шрифт), — не env: шаг валидации/сборки материализует
   производные из `brand.json` (см. §1). `lang` — из
   `VITE_DEFAULT_LOCALE` (и далее реактивно из i18n — `tz-i18n.md` §4.2).
3. **`pwa/manifest.ts`** уже модуль — берёт `name/short_name/theme_color`
   из instance-конфига; попутно чинится существующее расхождение
   (description на английском при `lang: 'ru'`).
4. Приёмка: два `.env` → две сборки, отличающиеся только именем, темой и
   иконкой вкладки; золотая сборка пиксель-в-пиксель равна текущей.

## 3. F2 — скин, слой 1

Контракт пакета — файлы с заранее заданными именами (дух §3.3 архитектуры:
скин — данные, не сборка; тестируем контракт, а не каждый скин):

| Файл пакета | Что переопределяет | Обязателен |
|---|---|---|
| `skin/tokens.css` | подмножество `--velo-*` из `src/styles/variables.css`, включая `--velo-tg-header`/`--velo-tg-bg` — их читает Telegram-хедер (`platform/telegram.ts:60`) | да |
| `skin/brand.json` | display name; short name (≤12 симв. — конвенция PWA); theme_color; background_color; семейство шрифта (опц., см. §7) | да |
| `skin/mandala-white.png`, `skin/velo-word-filled.svg` (+ синяя пара) | логотип: `VeloLogo.vue` рендерит `<img src="/icons/…">` — скин кладёт файлы по тем же путям | да |
| `skin/icon-192.png`, `icon-512.png`, `icon-maskable-512.png`, `apple-touch-icon-180.png` (непрозрачный — iOS красит прозрачность чёрным), `favicon.svg` | PWA/вкладка | да |
| `skin/bg/background.png` | мандала-фон `#app-bg` (рисуется `global.css`, красится первым пикселем экрана) | нет — фолбэк на эталон |
| `skin/onboarding/*.svg` | иллюстрации онбординга (`OnboardingView.vue:112`, абсолютные пути `/onboarding/…`) | нет — фолбэк на эталон |

Правила:

- **Применение — на сборке** (выкат = паспорт → пакет в `public/skin/`).
  Рантайм-смены скина нет: скин — свойство инстанса, не пользователя; это
  упрощает кэш сервис-воркера до обычного precache с content-hash.
- **Каскад токенов — не «сам собой»** (строгое ревью): порядок
  «tokens.css после variables.css» надо обеспечить механически — сборка
  материализует `src/styles/skin-tokens.css` (пустая заглушка, если скина
  нет) и `main.ts` импортирует его строго после `global.css`. Надежда на
  порядок ссылок в собранном CSS — не механизм.
- **Валидатор `scripts/validate-skin.mjs`** — пакет проверяется до
  применения: имена, размеры, форматы; **контраст-чек** переопределённых
  пар текст/фон, включая `--velo-tg-*` (пороги уже задокументированы в
  комментариях `variables.css`); `short_name` ≤ 12; safe-zone 80%
  maskable-иконки; непрозрачность apple-touch (правило — из собственного
  комментария index.html). Невалидный пакет не выкатывается.
- **Эталонные скины**: №1 — текущий VELO (отсутствие `skin/` = золотая
  сборка), №2 — намеренно контрастный тестовый. **Автотесты — не
  computed styles** (строгое ревью): happy-dom не надёжно резолвит
  `var()` из стилейheet — getComputedStyle-ассерты на токены будут
  флейвить. Вместо них: валидатор статически парсит `tokens.css`
  (имена/значения/контраст), DOM-тесты проверяют резолв путей ассетов;
  снимки экранов эталонов — ручная приёмка.
- **Бренд-текст — только через `{brand}`** из i18n (`tz-i18n.md` §7.2),
  не через скин: скин визуален.

## 4. F3 — редакции на фронте

Паттерны уже есть в коде — задача обобщить их:

- **Фича-реестр**: `VITE_FEATURES` → типизированный реестр модулей в
  `platform/instance.ts` (паттерн-предшественник — константа-kill-switch
  `COMPOSER_VOICE_INPUT` в `utils/constants.ts`). Единственная точка:
  никаких локальных `if (FEATURE_X)` вне реестра.
- **Роут-гейт**: маршруты модуля регистрируются только при включённом
  модуле; глубокая ссылка в выключенный модуль даёт штатную
  `NotFoundView`, а не белый экран. **Честно про «чанк физически не
  попадает в бандл»** (строгое ревью): условие через runtime-объект
  реестра Rollup не вырезает — dynamic import остаётся достижимым, чанк
  собирается. Два честных варианта: (а) флаги как статически заменяемые
  литералы — vite `define`/виртуальный модуль, материализуемый из
  паспорта, тогда DCE вырезает ветки вместе с чанками; (б) принять
  «чанк есть, но не регистрируется и не грузится». Рекомендация — (а):
  иначе греп-тест F5 «чанков выключенного модуля нет» невыполним.
- **Табы**: существующий механизм `requires` в `router/tabs.ts` (сейчас
  `'schools'`, фильтруется в `UserShell.vue:59` / `MasterShell.vue:46` по
  данным школы) расширяется edition-уровнем: `requires: 'payments' | 'ai' | …`
  — проверяется реестром, а не данными.
- Приёмка: сборка без `'payments'` не содержит роутов, табов и чанков
  платежей; deep-link даёт заглушку; золотая сборка неизменна.

## 5. F4 — i18n-швы

Не планируется здесь: локали per-инстанс, `{brand}`, оверлеи терминологии —
`tz-i18n.md` фаза 0.5 и §7. Стык с F2/F3: раскладка каталогов по модулям
(`tz-i18n.md` §4.1) совпадает с фича-реестром F3 — выключенный модуль не
грузит и свои строки.

## 6. F5 — приёмка whitelabel

1. **Сборочная матрица**: из одного коммита собираются VELO (золотой) + 2
   тестовых бренда; отчёт-диф ассетов и токенов.
2. **`scripts/validate-skin.mjs`** проходит на эталонах, валит битый пакет.
3. **Греп-тесты бренда**: «VELO» не встречается в пользовательских строках
   вне эталонного набора (стягивается с `tz-i18n.md` §7.2 — те ~8 мест);
   фича-флаги не разбросаны по файлам, а читаются только из реестра.
4. **Чек-лист инстанса**: манифест (name/short_name/description), иконки,
   theme-color, `lang`, бот-URL, локали — всё из конфига, ничего в коде.

## 7. Вне скоупа

Деплой-машина, хранение и раздача паспортов, центр, Zoom-пул, общие
практики, платежи, боты/comms — по архитектурному документу. Фронт готов
потреблять контракты §1 в любой момент: до их появления дефолты делают
сборку неотличимой от текущей.

**Границы брендирования, которые фронт не снимает** (строгое ревью):

- Интерфейс внутри встречи — Zoom Meeting SDK: он брендируется Zoom,
  не нами.
- Шрифт: сейчас Marmelad зашит в index.html (Google Fonts) и
  `--font-body` в `global.css`. Смена = `brand.json` → подстановка ссылки
  и токена; лицензию шрифта школы проверяет школа.
- Шапка и имя в Telegram — свойства бота инстанса (не фронт).

## 8. Риски

| Риск | Митигация |
|---|---|
| «Слегка подправить скин кодом» у конкретной школы | валидатор + греп-тесты F5 + правило «легаси нет»: одно отклонение = дыра в контракте |
| Фича-флаги расползаются по файлам (как `COMPOSER_VOICE_INPUT`) | единственный реестр в `platform/instance.ts`, греп-тест |
| Кэш сервис-воркера при смене скина | скин применяется на сборке → это обычный новый релиз; обновление без поломки открытого приложения уже решено платформой |
| Конфликт с i18n-миграцией | фазы F2/F3 не трогают строки; `{brand}`-места переносятся в фазе 3 `tz-i18n.md` — договориться очерёдность батчей |
