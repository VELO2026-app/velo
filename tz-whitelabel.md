## 0. Резюме

Цель фронтовой части: **один код собирается в N брендированных сборок
без правок кода** — только конфиг и скин-пакет. Всё остальное — следствия.

| Фаза | Что делается | Оценка |
|---|---|---|
| F1. Швы паспорта | конфиг-модуль, index.html/manifest/theme-color из конфига | 2–3 дня |
| F2.0. Токены-замок | новые токены, перенос сырых значений, stylelint (§3, дополнение 24.10) | 3,5–5 дней |
| F2. Скин, слой 1 | контракт пакета, валидатор, применение на сборке, эталонные скины | 5–8 дней |
| F3. Редакции на фронте | фича-реестр из паспорта, роут-гейт, табы, ленивые чанки | 5–8 дней |
| F4. i18n-швы | локали/`{brand}`/оверлеи инстанса — уже спланированы в `tz-i18n.md` | (там же) |
| F5. Приёмка whitelabel | сборочная матрица, валидатор пакета, греп-тесты бренда | 2–3 дня |

Итого фронт: **~4–5 недель**. Все фазы заканчиваются зелёным `pnpm verify`
и выкатываются независимо; золотая сборка (VELO без скина) бит-в-бит
сохраняется на каждом шаге.

**Статус и остаток — §9** (единственное место, где они ведутся).

## 1. Контракт входов (ред. 4: каналы по Праймеру)

Источник входов решён руководством «Как подготовить проект к деплой-машине
Праймера» (2.11). Правило (§4.1): **значения инстанса в сборку не попадают
никогда** — приходят при старте контейнера; в сборку легально входит только
свойство проекта — редакция и пакеты. `build.args` у compose — вне списка
разрешённого (§3.2), канал значений инстанса — `/config.json`, отрендеренный
envsubst'ом в nginx при старте (FE-129); на переходный период Vite-переменные
остаются для локальных сборок.

**Входит в сборку:**

| Вход | Дефолт | Кто потребляет |
|---|---|---|
| `PRIMER_RELEASE`, `PRIMER_COMMIT` | обязательны, без них сборка падает (§3.1) | идентификация релиза в образе |
| `PRIMER_EDITION` — имя редакции из `editions:` primer.yaml | нет = полная (золотая) сборка | фича-реестр F3 (FE-130) |
| скин-пакет — тег из слота `packages.skin` (`apply: build`) | отсутствует = эталон VELO | F2: токены, ассеты, theme-color, бренд-имя из бренд-записи пакета (`$extensions["velo-skin"]`) |

**Приходит при старте контейнера** (`/config.json`):

| Ключ `/config.json` ← env (`primer.yaml`) | Дефолт | Кто потребляет |
|---|---|---|
| `apiBaseUrl` ← `API_BASE_URL` (`domains.api`) | **ред. 10.11:** под машиной всегда непустой — **хост** API на своём домене, `https://` достраивает приложение (`normalizeApiBase`, FE-158). Пусто = same-origin `/api` — только локальная разработка и промежуточный стенд (прокси в nginx контейнера) | api-клиент (`platform`) |
| `telegramBotUrl` ← `TELEGRAM_BOT_URL` (шов comms) | текущий | вход/бот-ссылки |
| `defaultLocale` ← `DEFAULT_LANGUAGE` | `'ru'` | i18n `fallbackLocale`, дефолты `format.ts`, `<html lang>`, манифест (FE-155) |
| `locales` ← `LANGUAGES` (`en,ru,uk`, порядок паспорта) | `['ru']` | набор языков инстанса |
| опции ← `OPTION_PAYMENTS` … `OPTION_LLM` (`true`/`false`) | нет переменной = выключено | `isOptionEnabled` (FE-151, в работе) |

**Ред. 10.11 — бренд не значение старта.** `brand` из `/config.json` убран:
имя — `displayName` бренд-записи скин-пакета (`$extensions["velo-skin"]`),
материализуется на сборке; без скина — golden `VELO`. Неподставленный
плейсхолдер envsubst (`${NAME}` при отсутствующей переменной) считается
пустым значением (FE-158).

**Решение ред. 4 — локали.** `VITE_LOCALES` как build-фильтр несовместим с
машиной (набор локалей — `param` инстанса): собираются все каталоги (ленивые
чанки), язык по умолчанию выбирается при старте. Контроль размера бандла по
локалям теряется — принято.

**Производные идентичности.** Скин-часть (theme-color, цвета/иконки
манифеста, шрифт) материализуется на сборке из бренд-записи пакета
(`$extensions["velo-skin"]`); инстанс-часть (`name`/`short_name` манифеста,
`<html lang>`) — при старте контейнера (`<html lang>` и `lang`/`description`
манифеста — сделано, FE-155: сборка кладёт `manifest.<locale>.webmanifest`,
скрипт `nginx/40-manifest-locale.sh` выбирает файл по `DEFAULT_LANGUAGE`;
манифест вне precache SW) (`pwa/manifest.ts`, `index.html` — см. реестр исключений
§3.1).

**Единый источник «цвета шапки»** (строгое ревью): сегодня он живёт в трёх
несвязанных местах — `meta theme-color` `#334D6E` в index.html, CSS-токен
`--velo-tg-header` (его читает `platform/telegram.ts:60` с фолбэком
`#334d6e`) и `theme_color` манифеста. Контракт: бренд-запись пакета (`themeColor`) — единственный
источник, сборка порождает из него все три потребителя; иначе скин меняет
одно, а статусбар iOS и шапка Telegram остаются VELO-цвета.

## 2. F1 — швы инстанса (реализовано: FE-109)

1. **`platform/instance.ts`** — единственная точка чтения env: типизированный
   доступ + дефолты. Сегодня `import.meta.env.*` разбросан точечно (5+2
   вхождения) — свести в один модуль, чтобы новый шов добавлялся в одном
   месте.
2. **`index.html` из конфига**: паспортные плейсхолдеры `%VELO_BRAND%` /
   `%VELO_DEFAULT_LOCALE%` (значения — из `VITE_BRAND` / `VITE_DEFAULT_LOCALE`)
   подставляет плагин `platform/passport-html.ts`, с золотыми дефолтами.
   *(FE-153: раньше они писались `%VITE_*%`, и Vite на каждой сборке без
   `.env` предупреждал «is not defined in env variables».)* Значения, приходящие из скина
   (theme-color, шрифт), — не env: шаг валидации/сборки материализует
   производные из бренд-записи пакета (см. §1). `lang` — из
   `VITE_DEFAULT_LOCALE` (и далее реактивно из i18n — `tz-i18n.md` §4.2).
3. **`pwa/manifest.ts`** уже модуль — берёт `name/short_name/theme_color`
   из instance-конфига; попутно чинится существующее расхождение
   (description на английском при `lang: 'ru'`).
4. Приёмка: два `.env` → две сборки, отличающиеся только именем, темой и
   иконкой вкладки; золотая сборка пиксель-в-пиксель равна текущей.
5. **(ред. 4)** Точка чтения остаётся одна — `platform/instance.ts`; канал
   дополняется `/config.json` при старте контейнера (FE-129), локальные
   сборки продолжают читать Vite-переменные.

## 3. F2 — скин, слой 1

Контракт пакета — файлы с заранее заданными именами (дух §3.3 архитектуры:
скин — данные, не сборка; тестируем контракт, а не каждый скин). С FE-131
(09.11) носитель — DTCG-пакет машины (§3.2); поколение 1 (`brand.json` +
`tokens.css` в корне) сборкой больше не читается, мигрирует
`scripts/skin-to-dtcg.mjs`:

| Файл пакета | Что переопределяет | Обязателен |
|---|---|---|
| `primer-package.yaml` | `schema: 1`, `contract: "2.0"` — точка в кавычках (контракт 3 п.10); продукт читает `2.x` с Gen-2 токенов (FE-150), пакет `1.x` — отказ | да |
| `tokens/*.tokens.json` | W3C DTCG по путям `frontend/tokens.json`: `velo.*` (→ `--velo-*`) и единственный bare `bare.font-body` (→ `--font-body`), включая `velo.tg.header`/`velo.tg.bg` — их читает Telegram-хедер (`platform/telegram.ts:60`). Значение — CSS дословно, ссылка `{velo.…}` или список семейств | да (хотя бы бренд-запись) |
| `tokens/brand.tokens.json` → `$extensions["velo-skin"]` | display name; short name (≤12 симв. — конвенция PWA); themeColor; backgroundColor; `fonts` — самозахостенные шрифты (опц., см. §7) | да |
| `assets/mandala-white.png`, `assets/velo-word-filled.svg` (+ синяя пара), `assets/logo-white.svg` | логотип: `VeloLogo.vue` рендерит `<img src="/icons/…">` — сборка кладёт файлы по тем же путям | да |
| `assets/icon-192.png`, `icon-512.png`, `icon-maskable-512.png`, `apple-touch-icon-180.png` (непрозрачный — iOS красит прозрачность чёрным), `favicon.svg` | PWA/вкладка | да |
| `assets/bg/background.png` | мандала-фон `#app-bg` (рисуется `global.css`, красится первым пикселем экрана) | нет — фолбэк на эталон |
| `assets/onboarding/*.svg` | иллюстрации онбординга (`OnboardingView.vue:112`, абсолютные пути `/onboarding/…`) | нет — фолбэк на эталон |
| `assets/fonts/*.woff2` | шрифт бренда — `@font-face` в `skin-tokens.css` + preload в `index.html` вместо Google Fonts | нет |

Любой другой файл, симлинк или исполняемый файл — отказ (пакет — данные;
то же правило, что у `package.js` primer-blank; мусор ОС вроде `.DS_Store`
пропускается молча). Пакет — недоверенные данные: значение токена — закрытый
алфавит без кавычек, `\`, `;{}<>` и комментариев, с функциями только из
белого списка (`var`, `color-mix`, `rgb(a)`, `hsl(a)`, `cubic-bezier`,
`calc`/`min`/`max`/`clamp`) — ни `url()`, ни `image-set()`; каждое имя
семейства в `bare.font-body` проверяется отдельно; `displayName`/`shortName`
без `< > & "`; SVG — правила содержимого машины (без script, обработчиков,
`javascript:`, `foreignObject`, DOCTYPE/ENTITY, ссылок и `url()` наружу),
ужесточённые после ревью: без элементов с префиксом пространства имён,
числовых сущностей `&#…;`, `<style>` и `style=`, анимации, `src=`, `\`
(CSS-экранирование `u\72 l(` в атрибуте), инструкций обработки кроме
XML-декларации и пространства имён XSLT (эталон ничего из этого не
использует). Шрифт, JPEG и WebP проверяются по сигнатуре; в
`displayName`/`shortName` запрещены и управляющие символы направления
текста (U+202A–202E, U+2066–2069) и разделители строк; `initial`/`inherit`
/`unset` в `bare.font-body` — отказ; BOM и CRLF в манифесте допустимы.
**Ограничение:** значение токена — строка CSS, ссылка `{…}`, число или
список семейств; объектные формы DTCG (`{colorSpace, components}`,
`{value, unit}`), которые допускает формат машины, движок VELO пока
отвергает. Циклы ссылок (`{velo.primary}` на себя или
через golden-цепочку `var()`) — отказ.
Лимиты размеров свои, не машинные (эталонный логотип — 330 KB, фон
804×1748): SVG ≤ 512 KiB, PNG ≤ 4 MiB и ≤ 4096 px, шрифт ≤ 2 MiB. Ссылка
`{…}` не обходит контраст-чек: валидатор раскрывает её, а невычислимая
переопределённая пара — FAIL. В `dist/skin/` из пакета остаются только
`assets/fonts/` (чистится на каждой сборке, даже без скина); в precache они не входят, шрифт кэшируется рантайм-кэшем
сервис-воркера при первой загрузке. Движок один —
`scripts/lib/skin-package.mjs`: им проверяет `validate-skin.mjs` и им же
сборка (`platform/skin.ts`) конвертирует токены в CSS.

Правила:

- **Применение — на сборке** (ред. 4: выкат делает машина — слот
  `packages.skin` с `apply: build`: клонирует тег пакета из отдельного
  репозитория, сверяет `contract`, кладёт в контекст сборки — `public/skin/`;
  `apply-skin.mjs` остаётся dev-инструментом локальной примерки).
  Рантайм-смены скина нет: скин — свойство инстанса, не пользователя; это
  упрощает кэш сервис-воркера до обычного precache с content-hash.
- **Каскад токенов — не «сам собой»** (строгое ревью): порядок
  «токены скина после variables.css» надо обеспечить механически — сборка
  материализует `src/styles/skin-tokens.css` (пустая заглушка, если скина
  нет) и `main.ts` импортирует его строго после `global.css`. Надежда на
  порядок ссылок в собранном CSS — не механизм.
- **Валидатор `scripts/validate-skin.mjs`** — пакет проверяется до
  применения: имена, размеры, форматы; **контраст-чек** переопределённых
  пар текст/фон, включая `--velo-tg-*` (пороги уже задокументированы в
  комментариях `variables.css`); `short_name` ≤ 12; safe-zone 80%
  maskable-иконки; непрозрачность apple-touch (правило — из собственного
  комментария index.html). Невалидный пакет не выкатывается: `pnpm build`
  первым шагом гонит `validate-skin.mjs --build` (FE-148) — нет
  `public/skin/` = золотая сборка, есть каталог = полная проверка, в том
  числе каталог без `primer-package.yaml` (иначе сборка тихо сочла бы его
  «без скина»). Это и есть место проверки: у пакета `apply: build` слота
  `validate:` нет (контракт 3 п.31 — только при `runtime`).
- **Эталонные скины**: №1 — текущий VELO (отсутствие `skin/` = золотая
  сборка), №2 — синтетический контрастный пакет, который CI пишет во
  временный каталог (`scripts/make-test-skin.mjs`: эталонные ассеты,
  контрастная палитра, шрифт) и собирает скин-ячейкой матрицы на каждом PR.
  Скинов в `velo` нет вовсе (FE-131): репозиторий публичный, бренд
  партнёра — свой приватный пакетный репозиторий; локально — по пути к
  пакету (`build:matrix --skin <путь>`, `VELO_SKINS=<путь> pnpm storybook`).
  Скин-ячейка матрицы проверяет и раскладку: ассеты побайтно на `/icons`,
  `/bg`, `/onboarding`, в `dist/skin/` только шрифты, у каждого шрифта —
  `@font-face` и preload. **Автотесты — не
  computed styles** (строгое ревью): happy-dom не надёжно резолвит
  `var()` из стилейheet — getComputedStyle-ассерты на токены будут
  флейвить. Вместо них: валидатор статически читает токены пакета
  (имена/значения/контраст), DOM-тесты проверяют резолв путей ассетов;
  снимки экранов эталонов — ручная приёмка.
- **Бренд-текст — только через `{brand}`** из i18n (`tz-i18n.md` §7.2),
  не через скин: скин визуален.

### 3.1. Дисциплина токенов — замок скина (дополнение 2026-10-24)

По принципам инстансов от 22.10 (§5.7): хорошо ли ляжет скин, решает не
фреймворк, а то, что компоненты не обходят токены. Один зашитый `#334D6E` —
и скин партнёра в этом месте показывает цвет VELO, а контрактный тест
пакета этого не заметит. Правило: **ни одного сырого цвета, размера
шрифта, радиуса или тени в компонентах — только через `--velo-*`**;
закрепляется stylelint (`*.vue` и `*.css`, через postcss-html): сырые
значения вне `variables.css` — ошибка сборки. Новые shell-скрипты не
заводятся.

**Перебор перед введением правила** (2026-10-24). Метод: все `.vue`/`.css`
вне `variables.css`; из счёта исключены значения внутри `var(…, фолбэк)`
(легальный паттерн «токен-первым», его в коде много), ключевые слова
(`transparent`/`inherit`/`none`/`0`) и ложные попадания в комментариях.
Итог — **166 значений в 55 файлах** (цвета 112, font-size 29, радиусы 17,
тени 8):

| Кластер | Сколько | Куда |
|---|---|---|
| дубликаты существующих токенов: `#4c6589` ×15, `#627a9c` ×3, mood/rating-цвета в SVG-иконках ×14, одиночные | ~40 | механическая замена на `var(--velo-…)` |
| белый/чёрный альфа-ряды, «стекло», туманы, тени: `Composer.vue` (25), `VTabBar`, `VBottomSheet`, фог-градиенты чата/админки (`#000` ×27), `global.css` (5) | ~60 | новые токены: `--velo-glass-white-*`, `--velo-fog-color`, `--velo-shadow-sheet/card`, рецепт композера в `--velo-write-*` |
| пастели-одиночки: `#f9cbd1`, `#bdecf1`, `#fddfc4`, `#e2f0fd`, `#619cd2` | ~9 | токены по роли экрана, не по hex |
| font-size (грязнейшие: `DiaryThreadCard` 11, `AdminMasterReviewView` 17 вместе с радиусами) | 29 | `--velo-fs-*`: 10/11/12/13/14/18/22/24/25/28/48px |
| border-radius | 17 | `--velo-radius-*`: 4/8/10/12/22/31px, `pill` (999px), составные (`--velo-radius-sheet-top` = `30px 30px 0 0`) |
| box-shadow | 8 | рецепты целиком одним токеном (по образцу `--velo-shadow-glow`) |

Решение владельца и бэка (24.10): **типографика и радиусы входят в
поколение 1 контракта пакета**, вместе с цветами и ассетами. Следствие:
после шага 3 любой новый токен добавляется свободно, переименование или
удаление = поколение 2.

**Порядок переезда.** Каждый шаг — отдельный PR; эталон пиксель-в-пиксель
не меняется; значения переносятся 1:1, «заодно нормализуем» запрещено.

| Шаг | Что | Оценка |
|---|---|---|
| 0. Фундамент | новые токены в `variables.css` (значения = текущие), stylelint локально (CI пока не блокирует), grep-тест: цвет в `*.ts` вне реестра исключений — красный | 0,5–1 д |
| 1. Цвета, три батча | (а) дубликаты токенов → (б) стекло/туманы/тени → (в) пастели; после каждого батча — тесты и ручной взгляд на экраны (включая write-режим композера) | 1,5–2 д |
| 2. Типографика и радиусы | от грязных файлов к хвостам, по файлу за заход; разрешены только `var(--velo-fs-*/radius-*)`, `inherit`, `0` | 1–1,5 д |
| 3. Замок и контракт | stylelint = ошибка сборки в CI; в `variables.css` — раздел «контракт пакета, поколение 1»: таблица «токен ↔ имя DTCG» | 0,5 д |

Итого F2.0: **~3,5–5 дней**. Проверить в первом же PR: inline-SVG в иконках
подхватывает `var()` во `fill` (проба на одном `IconMoodScale*`).

**Реестр исключений** — явным списком с причиной; для `*.ts` закрепляется

  аналитических токенов из `variables.css`; тот же паттерн «токен-первым»,
  закреплён grep-тестом шага 0.
- `pwa/manifest.ts`, `index.html` — уходят в генерацию на старте
  контейнера (принципы 22.10); до переезда числятся в реестре.

Отдельное решение после заморозки контракта (не в этом рефакторинге):
консолидация 12 ступеней белого альфа-ряда до 3–4 — визуальное изменение,

### 3.2. Носитель пакета — репозиторий Праймера (ред. 4)

Формат репозитория пакета по руководству §4.4 и контракту 3 п.10:
`primer-package.yaml` в корне (`schema`, `contract` — **точка** `"X.Y"`:
версию пакета объявляет точкой, полуоткрытый диапазон — только в слоте
`packages.skin` продукта, операторы `==`/`===`/`<=` запрещены, п.3),
`tokens/*.tokens.json` — W3C DTCG, `assets/`; кода в пакете нет, выпуски —
теги `vX.Y.Z`, выпущенные теги не переписываются. Эталонные скины выезжают
из репо продукта в пакетный репозиторий (FE-131). **Формат решён (2.11,
владелец): DTCG** — пакет поколения 1 (`brand.json` + `tokens.css`)
конвертируется на `tokens/*.tokens.json`; мост — таблица «токен ↔ имя DTCG»
в `variables.css` (шаг 3 F2.0), пайплайн — трек T (§3.3, FE-124); мета-поля поколения 1 (бренд-имя, шрифт) переезжают в структуру
пакета по руководству §4.4. **Сделано (FE-131, 09.11):** пути токенов пакета
= пути `frontend/tokens.json`; бренд-запись — `$extensions["velo-skin"]`
(`displayName` сохраняется — на нём держится удаление `VITE_BRAND`, FE-148);
шрифт — только самозахостинг в `assets/fonts/` (внешний `fontUrl` пакет
отвергает); партнёрский скин вынесен в отдельный приватный репозиторий
`VELO2026-app/goodo-brand` (тег `v0.2.0`, contract `2.0` под Gen-2 токенов, FE-150) и из `velo` удалён — `velo`
публичный, бренды партнёров в нём не живут. Машинный `package.js` primer-blank не взят:
его 5 DTCG-типов не выражают значения VELO (`rgba()`, `color-mix()`, тени,
`var()`-цепочки) — раскладка файлов, правило «только данные» и проверки
содержимого SVG совпадают, лимиты размеров и движок свои. Переговоры с Праймером о приёме `tokens.css`
не нужны. Всё проверяемое содержание контракта §3 (обязательные токены,
контраст-чек, safe-zone, непрозрачный apple-touch) переносится на новый
носитель без изменений; в build-режиме негодный пакет роняет сборку —
`validate-skin.mjs --build` первым шагом `pnpm build` (FE-148; слот
`validate:` у `apply: build` не предусмотрен, контракт 3 п.31).

- **Сверка с бэком (ред. 4)**: соответствие «редакция → модули» — таблица
  проекта, одна на репозиторий, её читают и бэк, и фронт; бэк закрывает

   пакет `scripts/make-test-skin.mjs` во временном каталоге раннера.)*
2. **`scripts/validate-skin.mjs`** проходит на эталонах, валит битый пакет.
3. **Греп-тесты бренда**: «VELO» не встречается в пользовательских строках
   вне эталонного набора (стягивается с `tz-i18n.md` §7.2 — те ~8 мест);
   фича-флаги не разбросаны по файлам, а читаются только из реестра.
4. **Чек-лист инстанса**: манифест (name/short_name/description), иконки,
   theme-color, `lang`, бот-URL, локали — всё из конфига, ничего в коде.
5. **(ред. 4)** Матрица остаётся CI-проверкой проекта; третий параметр
   сборки — `PRIMER_EDITION`: каждая редакция конечна и собираема на
   тест-сервере (руководство §4.2). *Ред. 10.11: после замены
   `editions.json` матрица сужается до golden × `ai` × скин; ячейки «без
   `payments`» уходят — платежи стали опцией (FE-152, комментарий 10.11).*

## 7. Вне скоупа

Деплой-машина, хранение и раздача паспортов, центр, Zoom-пул, общие
практики, платежи, боты/comms — вне фронта; с 2.11 выкладку и паспорта
ведёт деплой-машина Праймера — руководство «Как подготовить проект к
деплой-машине Праймера» фиксирует границу: проект видит со стороны машины
только `primer.yaml`, `/config.json`, пакеты и режим сборки. Фронт
потребляет контракты §1; до прихода машины дефолты делают сборку
неотличимой от текущей. Смежное (дополнение 03.11, протокол v1.5 §4.5–4.7):
`comms-profile/` — форма Г «Данные» — **остаётся каталогом продукта**, одни
на все инстансы: копия → `validate --profile` comms (отказ останавливает
выкат продукта) → перезапуск comms → новый код продукта; меняется в два
выката (§4.6), только сужает (§4.7). Слот `texts` — пакет инстанса поверх
базового профиля: часть `from: ui` (оверлеи терминологии, `tz-i18n.md` §7)
и часть `from: comms` (`PROFILE_OVERLAY_DIR`, контракт 3 §1); стык — FE-133.

**Границы брендирования, которые фронт не снимает** (строгое ревью):

- Интерфейс внутри встречи — Zoom Meeting SDK: он брендируется Zoom,
  не нами.
- Шрифт: сейчас Marmelad зашит в index.html (Google Fonts) и
  `--font-body` в `global.css`. Смена шрифта скином (FE-131, решено):
  только самозахостинг — `assets/fonts/*.woff2` пакета, перечисленные в
  `fonts` бренд-записи; сборка пишет `@font-face` и заменяет блок Google
  Fonts в `index.html` на preload своих файлов; `bare.font-body` обязан
  назвать это семейство. Внешний `fontUrl` пакет отвергает. Лицензию
  шрифта школы (право на самохостинг) проверяет школа.
- Шапка и имя в Telegram — свойства бота инстанса (не фронт).

## 8. Риски

| Риск | Митигация |
|---|---|
| «Слегка подправить скин кодом» у конкретной школы | валидатор + греп-тесты F5 + правило «легаси нет»: одно отклонение = дыра в контракте |
| Фича-флаги расползаются по файлам (как `COMPOSER_VOICE_INPUT`) | единственный реестр в `platform/instance.ts`, греп-тест |
| Кэш сервис-воркера при смене скина | скин применяется на сборке → это обычный новый релиз; обновление без поломки открытого приложения уже решено платформой |
| Перенос токенов (F2.0) незаметно меняет вид | значения 1:1, никаких нормализаций по пути; батчи с ручной приёмкой; эталон-инвариант на каждом PR |
| Конфликт с i18n-миграцией | фазы F2/F3 не трогают строки; `{brand}`-места переносятся в фазе 3 `tz-i18n.md` — договориться очерёдность батчей |
| Дрейф `primer.yaml` (слоты, `editions`) ↔ контракт этого ТЗ | этот документ — источник контракта пакета; `pridem check` в CI (после DM-57); ревью слота при каждом новом поколении контракта |
| Остаточные `VITE_*` в коде после переезда на `/config.json` | FE-129 вычищает build-args; чтение env только в `platform/instance.ts` (греп-тест F1) |

## 9. Статус и остаток — единый план (кит + whitelabel → партнёрское решение)
