## 1. Принципы (наследуются из tz-whitelabel)

1. **Миграция не трогает потребителей.** `views/`, `shared/`, `admin/` продолжают
   импортировать из `@/components/ui`; баррел внутри себя переключается
   с локальных файлов на `@velo/ui` по компоненту. Приложение замечает переезд
   только когда локальная копия удаляется — и то не меняя ни одного импорта.
2. **Токены не уезжают.** Пакет не содержит значений темы — только правила с
   `var(--velo-*)`. `variables.css` остаётся в приложении (контракт пакета,
   поколение 1). Следствие: скин и золотая сборка красят пакет одинаково.
3. **Один компонент за заход** в пределах батча; батч = PR. Порядок — от листьев
   к корням по графу зависимостей (§2), не по алфавиту.
4. **Доменное — не пакет.** Всё, что знает про Telegram, школы, настроения,
   роли, — остаётся в приложении (см. исключения в §0, `useKeyboardFieldScroll`).
5. **Гибкость — данными, не форками** (бенчмарк §7). Скин, вариант и тема —
   данные (токены, пресеты, props), а не ветвления в CSS или коде компонента.
   Строго — к контракту (токены, типы, имена, атрибуты), гибко — к данным.

## 3. P1 — каркас (2–3 дня) — ✅ выполнено (FE-116; Storybook — 17 сторий)

1. **`pnpm-workspace.yaml`** в корне: `frontend`, `packages/*`. Корень получает
   `private: true`, общие devDeps (typescript, eslint, stylelint, prettier,
   vitest) поднимаются на уровень воркспейса.
2. **`packages/velo-ui`**: `private: true`, `exports` через `.`,
   `peerDependencies: { vue: ^3.5 }`; vite lib-mode,
   `vue-tsc` для dts, свой vitest (настройка = текущий `test-setup.ts` +
   golden-стаб бренда из b91e259f), stylelint с тем же токен-замком (пакет
   под тем же законом §3.1).
3. **Стратегия CSS**: стили компонентов едут в пакете как есть (`*.vue` SFC),
   значения — только `var(--velo-*)`. Порядок подключения: `main.ts` приложения
   импортирует css-бандл пакета строго после `variables.css` и строго до
   `skin-tokens.css` — каскад из tz-whitelabel §3 не ломается. **Первый PR
   батча A проверяется на бит-в-бит чанках и визуальную пиксельность** до
   продолжения батча.
4. **Storybook поднимается в P1, а не в P7**: скелет витрины + одна сторя.
   Дальше каждая сторя пишется в своём батче (P2–P6) — иначе конец миграции
   получит crunch из 35 сторей и приёмку задним числом.
5. **Структура: папка на компонент** (бенчмарк §7.2 — анатомия
   `button/{BaseButton.vue, Button.vue, Button.d.ts, Button.spec.js, style/}`
   у PrimeVue): `src/components/VButton/{VButton.vue, VButton.test.ts,
   VButton.stories.ts, index.ts}` — тест и сторя колокализованы с
   компонентом, а не в плоских каталогах. Баррел пакета собирается из
   папочных `index.ts`; каждый тест, переезжающий из `components/ui`,
   ложится в папку своего компонента.
6. **Contract-тест токенов**: пакет зависит от ДВУХ семей токенов
   `variables.css` — 161 `--velo-*` и 43 «голых» (`--space-*`, `--text-*`,
   `--radius-*`, `--shadow-*`, `--z-*`, `--font-*`, `--transition-*`,
   `--size-*`; нейминг заморожен, PROMPT №437 — не унифицировать). Тест по
   образцу `styles/token-law.test.ts` сканирует стили пакета: каждый
   `var(--…)` обязан входить в контракт пакета (README) и в `variables.css`
   золотой сборки. Без этого перенос молча ломает любого второго потребителя.
   Плюс **tier-правило** (§7.3): компонентам пакета разрешены семантические
   и компонентные уровни токенов; примитивы (hex, сырые значения) запрещены —
   `color-no-hex` в stylelint уже первый слой, tier-слой фиксируется в
   README-контракте.
7. Приёмка: приложение ничего не импортирует из пакета, всё зелёное,
   диффов сборки нет.

### 3.7. Storybook-витрина: скоуп, скин-режим, критерий закрытия (дополнение 07.11)

Витрина остаётся в плане как **минимальный детерминированный рендер-стенд**,
не продуктовый инструмент. Обоснование: (1) приёмка P2–P6 — «сторя ↔
Figma-фрейм» сверяется только на одинаковых изолированных рендерах;
(2) скины — витрина единственное место, где один компонент виден под всеми
скинами одновременно (в приложении скин один на сборку, в Figma значения
подставлены вручную) — демо-артефакт для whitelabel-партнёра.

- **Скоуп — только кит**: компоненты `@velo/ui`, доки токенов,
  скин-переключатель. Доменные композиты из `components/shared/` и
  иллюстрации в витрину **не заводятся** — это половина стоимости владения.
- **Шаг 1 витрины** (поверх существующих 17 сторий; ~0,5–1 день после P8):
  1. доки токенов — страница с живыми `--velo-*` пакета (значения = данные,
     смена скина перекрашивает стори сама);
  2. скин-переключатель — декоратор, подменяющий токен-файл на эталонные
     скины (golden / намеренно контрастный test; партнёрские — по мере
     появления): компонент под всеми скинами на одном экране.
- **Не докупаем экосистему** (Chromatic, zeroheight): стенд нужен
  детерминированный, не продуктовый; визуальный дифф остаётся ручной
  скриншот-сверкой (§4 P2).
- **Критерий закрытия**: если через квартал после P8 витрину никто не
  открывает (скины проверяются `validate-skin.mjs` статикой, приёмка ушла
  в тесты) — заморозить/убрать без сожалений. Страховка от «мёртвого
  сторибука» — главного риска владения.

### P3 — i18n-шов (1–1,5 дня) — ✅ выполнено (FE-118, PR #32, в `test`)

Решение ред. 2 — **инъекция транслятора, без vue-i18n в peer**. Основание
(аудит §2.1): 9 компонентов импортируют `t = i18n.global.t` из `@/locales`,
`useI18n()` не используется ни разу; все ключи статические (без параметров и
плюралов). Словарь `ui.*` остаётся в приложении — вне `components/ui` он
используется ещё 98 раз.

1. Контракт пакета: экспорт `configureUi({ t })` (сеттер транслятора) и
   `UI_I18N_KEYS` / тип `UiMessageKey` — список требуемых ключей (8
   статических + семьи `ui.dayFull.*`, `ui.dayShort.*`). Хост в `main.ts`
   передаёт свой `t`; вызовы `t('ui.…')` внутри компонентов пакета **не
   меняются**. До `configureUi` пакет в dev-режиме предупреждает (молчаливый
   рендер «ключей вместо текста» запрещён).
2. Выравнивание реестра (только этот PR — это часть шва, не «заодно»):
   `VMenu` → `ui.menuAria`, `VBarChart` → `ui.noData`; новые ключи добавляются
   в `locales/{ru,en,uk}/ui.json`. Зависимость пакета от app-неймспейсов
   `shared.*` / `common.*` обнуляется.
3. `key-audit.mjs` дополняется проверкой: все `UI_I18N_KEYS` резолвятся в
   `locales/` приложения во всех трёх локалях.
4. Перенос: VAccordion, VBarChart, VDayPicker. `VeloLogo` не переносится
   (домен-скин, §0).

## 7. Бенчмарк: PrimeVue (ред. 3, 28.10.2026)

Вопрос: как быть одновременно гибким и строгим в дизайне и коде. Эталон —
**PrimeVue 4** (14,4k★, MIT), разобран по репозиторию 28.10; контраст —
Vuetify (41k★; TSX + Sass, дефолты через defaults-provider), Element Plus
(27,8k★; SCSS → `--el-*`, BEM-фабрика `useNamespace`, пакет `locale` с
инъекцией провайдером), Reka UI (6,9k★; headless — строгое поведение, ноль
стилей). Эталон выбран потому, что PrimeVue решает «гибкость vs строгость»
на нашей оси: стилизованные SFC-компоненты + токены хоста.

### 7.1. Формула

**Строго — к контракту, гибко — к данным** (принцип 5, §1). Токены
трёхуровневые и типизированные, компонент потребляет только токены; вся
вариативность (скины, варианты, тёмная тема) — данные (пресеты, props),
а не форки CSS. Совпадает с принципом tz-whitelabel «скин = данные» —
бенчмарк подтверждает курс, а не меняет его.

### 7.2. Код: что берём

| Механизм PrimeVue | Эквивалент в `@velo/ui` |
|---|---|
| Папка на компонент: `BaseButton.vue / Button.vue / Button.d.ts / Button.spec.js / style/` | `VButton/{VButton.vue, VButton.test.ts, VButton.stories.ts, index.ts}` (§3.5): тест и сторя колокализованы |
| `inheritAttrs: false` + явный `mergeProps(...)` на корень | правило для сложных компонентов (VModal, VMenu, VInput): attrs потребителя попадают в задокументированный узел, не «куда Vue решит» |
| `data-p-*` дата-атрибуты состояний (`data-p-disabled`, `data-p-severity`, …) | стандарт `data-velo-*`: `data-velo-loading/disabled/invalid/…` — машинный слой поверх BEM-модификаторов; на нём тесты, скин-переопределения и Code Connect (P7) |
| Pass-through (`pt`) на каждый внутренний узел | целиком НЕ берём (overkill для приватного пакета); эквивалент — слоты для всех внутренних узлов + `data-velo-*` |
| `cx()`/`cn()` хелперы классов и дата-атрибутов | не нужны — computed-классы SFC; именование остаётся BEM (`v-button__label`) |
| `provide: { $pcButton }` — контекст детям | provide/inject-швы P5 (useToast-провайдер, behavior-инъекция для полей) |

Сознательно НЕ берём: **рантайм-движок тем** (`useStyle`, генерация CSS из
JS-пресетов) — нарушает принцип 2 «токены не уезжают» и ломает статичный
каскад `variables.css → пакет → skin-tokens.css`; **TSX-рендеры** (путь
Vuetify) — у нас SFC + vue-tsc + Storybook; **Base-наследование** options
API — эквивалент в `<script setup>`: композаблы и фабрики пропсов, не
классы-предки.

### 7.3. Дизайн: токены

Три уровня у PrimeVue: **примитивы** (`{sky.500}`) → **семантика**
(`{primary.color}`, `{form.field.padding.x}`) → **компонентные** токены
(`root` + `colorScheme.light/dark`, camelCase), значения компонентного
уровня — только ссылки наверх; контракт типизирован
(`satisfies ButtonDesignTokens`); пресеты (Aura/Lara/Nora/Material) —
данные, кастомизация через `definePreset`; тёмная тема — ветка
`colorScheme.dark` в тех же данных, не отдельные стили.

Для `@velo/ui` без смены архитектуры: в CSS-контракте пакета разрешены
семантический и компонентный уровни, примитивы запрещены (tier-правило,
§3.6 — stylelint `color-no-hex` уже первый слой); скины — DTCG-данные
трека T (структурно = пресеты PrimeVue, только на этапе сборки, без
рантайма); тёмная тема при появлении — тоже данные скина, не новые CSS.

### 7.4. Косвенные подтверждения решений этого ТЗ

- Локаль через провайдер у Element Plus (пакет `locale` + инъекция) —
  подтверждает `configureUi({ t })` (P3, вариант «b»).
- Иконки отдельным пакетом у PrimeVue (`@primeuix/icons`-стек) и Element
  Plus (`@element-plus/icons-vue`) — подтверждает сабпас `@velo/ui/icons` (P4).
- Колокализованные тесты у PrimeVue (`Button.spec.js`) и Vuetify
  (`__tests__/`) — подтверждает структуру §3.5 и правило «тест до переноса».
- Пакет `mcp` у PrimeVue (MCP-сервер для агентов) — напоминание, что витрина
  и метаданные (P7) скоро потребуются не только людям.
