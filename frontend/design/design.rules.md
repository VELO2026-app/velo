# design.rules.md — правила превращения дизайна в код

> Для кого: агент (или человек), который берёт макет/дизайн (Figma Dev Mode MCP, PNG-экспорт, словесное описание) и реализует его в этом репо.
> Основание: ТЗ фабрики п. 11.2. Карта компонентов — [component-map.md](./component-map.md). Токены — `src/styles/variables.css` (156 `--velo-*`, сгруппированы).

## 1. Дизайн — это представление, а не код

Выход Figma MCP / экспорта / описания — представление дизайна. Это не готовая разметка: её переводят в компоненты и токены этого проекта по правилам ниже. Дословный перенос сгенерированной вёрстки — дефект, а не результат.

## 2. Только токены

- Tailwind/generic-классы и «примерные» цвета заменяются токенами `--velo-*` из `src/styles/variables.css`.
- Хардкод hex/px в вью и компонентах запрещён (исключение — сам `variables.css`). CI-гейт и ревью это ловят.
- Нет токена под нужное значение → не изобретать: вопрос владельцу с предложенным ответом («нужен семантический warning-фон, беру `--velo-warning-bg`, ок?»). Создание новых токенов — через владельца (правило «не плодить варианты» — см. `deliberately-not-fixed.md`).

## 3. Только компоненты из карты

- Компоненты — из [component-map.md](./component-map.md), импорт через барелы `@/components/ui` и `@/components/icons`.
- Иконочные пакеты (lucide, heroicons, …) не подключать. Новая иконка = SVG-компонент в бареле.
- Нового компонента в DS без обновления карты не бывает; фичевые композиты ищутся сначала в `shared/`.

## 4. Править, а не плодить

Существующий экран — правкой существующего view-файла. Новый экран = новый view + маршрут, согласованные в карточке задачи. Дубли вида `CreateXView`-копия-`EditXView` — запрещены (см. Фаза 3г: это долги, которые разгребают, а не умножают).

## 5. Состояния и доступность — часть «готово»

Каждый управляемый блок несёт loading / success / empty / error-состояния; focus visible, aria-атрибуты (образец — `aria-selected` на сегментах), клавиатурный проход. Чеклист идиом — `VELO-Anti-Patterns.md` и шапки существующих экранов.

## 6. Геометрия — мобильный first

Узкий экран — основной кейс; safe-area через `useSafeArea`; скролл-контейнеры и поведение софт-клавиатуры продумывать сразу (границы: не теснится ли верхняя полоса, не перекрывает ли клавиатура композер).

## 7. Самопроверка

- **Сейчас (до tgqa P0):** узкий тест экрана/компонента → полный гейт (`typecheck → test → lint → build`) → скрин на устройстве/симуляторе для всего, что вёрстка.
- **После tgqa P0:** визуальный дифф против зафиксированного экспорта — оракул «похоже/не похоже», вердикт за человеком.

## 8. Эскалация

Всё, чего нет в карте, в токенах или противоречит существующему канону — вопросом владельцу **с предложенным ответом и ценой каждого варианта**, никогда молчаливой импровизацией. Приёмка UI — скилл `verify-frontend-ui` по критериям из Linear.
