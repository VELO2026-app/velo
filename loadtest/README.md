# Нагрузочный тест VELO — как запустить

Тест запускаете вы сами, со своего Mac, против сервера `dev`
(`https://api.zxcvbnm.beer`). Программа сама создаёт нагрузку, сама снимает
цифры с сервера и в конце открывает в браузере готовый отчёт. Все цифры в
отчёте получены в вашем прогоне.

Ниже две части: **разовая подготовка** (один раз на этом Mac) и **запуск**
(каждый раз). Каждая команда записана полностью — вводите её целиком, ровно
столько раз, сколько она встречается.

---

## Разовая подготовка

### 1. Терминал и Python

Откройте программу «Терминал» (Программы → Утилиты → Терминал). Введите:

```
python3 --version
```

Если macOS предложит установить «инструменты командной строки» — согласитесь
и дождитесь конца установки. Можно поставить их и командой:

```
xcode-select --install
```

После установки проверьте ещё раз:

```
python3 --version
```

Ответ должен быть `Python 3.9` или новее.

### 2. Доступ к серверу

У вас есть доступ к серверу `dev` по ssh-ключу. Проверьте его, подставив свой
адрес входа вместо `root@zxcvbnm.beer`, если он у вас другой:

```
ssh root@zxcvbnm.beer velo version
```

В ответе должна быть строка `Repo HEAD:`. Если ssh спрашивает пароль или
отвечает `Permission denied` — доступа по ключу нет, тест не запустится.

### 3. Код теста

```
cd ~
```

```
git clone https://github.com/VELO2026-app/velo.git velo-loadtest
```

### 4. Данные теста на сервере (единственная команда на сервере)

Войдите на сервер:

```
ssh root@zxcvbnm.beer
```

Создайте мастеров теста:

```
velo seed --profile 11102026-loadtest
```

Ответ кончается строкой `seeded: 11 masters`. Выйдите с сервера:

```
exit
```

Больше на сервере руками ничего не делается: всё остальное программа делает
сама, командой `velo loadtest-probe`, только чтение.

---

## Запуск

### 5. Перейти в код теста и обновить его

```
cd ~/velo-loadtest
```

```
git pull
```

### 6. Запустить

Быстрый прогон — тесты 3, 4 и 1, около 40 минут (первый раз — плюс около
20 минут на вход 1600 учеников):

```
python3 loadtest/run.py --ssh root@zxcvbnm.beer
```

Полный прогон — ещё тест 2 (15 минут) и тест 5 (60 минут):

```
python3 loadtest/run.py --full --ssh root@zxcvbnm.beer
```

Программа спросит **токен бота `dev`**. Вставьте его и нажмите Enter — на
экране он не появится, в истории команд и в файлах не останется.

Первый запуск скачает k6 v2.3.0 с GitHub в `loadtest/.bin/` и сверит его
контрольную сумму с официальной; без совпадения программа остановится.

### 7. Результат

Когда всё готово, программа печатает

```
✓ Отчёт: …/loadtest/results/<дата-время>/report.html
```

и открывает отчёт в браузере. Рядом с отчётом лежат исходные данные прогона:
сводки k6, временные ряды, ответ сервера.

Если что-то пошло не так, программа пишет `✗ Остановлено:` и причину, а
знака `✓` не будет. Практики, созданные прогоном, она отменяет и в этом
случае.

Прогон можно остановить в любой момент: Control + C.

---

## Что делает прогон

1. Проверяет k6 и спрашивает токен.
2. Спрашивает сервер: `velo loadtest-probe check` — роль, код, железо.
3. Учеников теста (телеграм-номера 710001…) входит на сервер в темпе
   86 входов в минуту — у сервера лимит 100 входов в минуту с одного адреса.
   Сессии хранятся в `loadtest/.state/sessions.json` только на этом Mac;
   следующий прогон их переиспользует.
4. От имени мастеров теста создаёт практики этого прогона: ленту (100 практик),
   практику на 20 мест для гонки и практику «начало» через 15 минут.
5. `velo loadtest-probe start` — сервер начинает замеры CPU, памяти и
   соединений.
6. Тесты: пик перед началом практики (3), гонка за места (4), излом (1);
   в полном прогоне — ещё рабочая нагрузка (2) и час (5).
7. `velo loadtest-probe stop` — сервер отдаёт замеры и ничего у себя не
   оставляет.
8. Отменяет все практики прогона и проверяет, что активных не осталось.
9. Строит отчёт.
